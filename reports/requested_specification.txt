# 1. PRIMARY OBJECTIVE

Build BLOCK as a machine-readable, research-grounded combat reasoning and cinematic fight-direction engine.

Given two fighter cards, the engine must:

1. Retrieve each fighter's complete combat configuration.
2. Resolve their fighting styles, guards, defenses, stances, grappling, target preferences, kicking systems, and mentalities.
3. Identify advantages, disadvantages, compatibility, and exploitable weaknesses.
4. Calculate a deterministic, reproducible model-derived win probability.
5. Explain the mechanisms behind that probability.
6. Determine which fighter is more likely to establish their preferred fight.
7. Identify the first reachable weakness, subsequent vulnerabilities, and opportunities for reversal.
8. Plan a temporally coherent fight with opening exchanges, tactical adjustments, turning points, and a justified conclusion.
9. Resolve techniques into structured actions, reactions, positions, and causal events.
10. Translate the fight into coherent cinematic choreography.
11. Produce machine-readable shot lists and AI-video prompt packages.
12. Validate consistency between the fighter cards, predicted result, fight events, and visualization prompts.

The system must support two outcome modes:

- **Predictive:** The engine computes probabilities and samples a winner reproducibly using a recorded random seed.
- **Director-controlled:** The author selects a winner, and the engine constructs a plausible, explicitly labeled dramatized path to that result without falsifying the original prediction.

Distinguish model-derived probability from empirically calibrated real-world win probability. Do not imply the former has been statistically validated as the latter.

## Foundational rule

**Every fighting style buys an advantage by accepting a liability. A fight is determined by which fighter can reach, exploit, and capitalize on the opponent's liabilities first.**

Never equate a numeric style tendency with overall power.

Never create universally dominant styles.

All advantages must be conditional on tactical circumstances.

# 8. IMPLEMENT THE PREDICTION ENGINE

Create `predict.py` or an equivalent importable engine with that CLI entry point.

The engine must:

1. Load two cards.
2. Validate schemas and canonical references.
3. Resolve each applicable matchup matrix.
4. Resolve both attack/defense directions for asymmetric matrices.
5. Evaluate compatibility.
6. Evaluate reachable exploits.
7. Apply dimension weights.
8. Apply synchronized-slot advantages.
9. Apply exploitable NULL penalties.
10. Convert the final score into a logistic probability.
11. Generate a complete prediction trace.

Required slot rules:

- Add +0.15 for each net additional synchronized slot.
- Apply -0.20 for each reachable, exploitable NULL capability.

Define precisely how these terms enter the logit so fighter order is handled symmetrically and bonuses are not double-counted.

The engine must produce consistent results when fighters A and B are exchanged:

`P(A beats B) + P(B beats A) = 1`

within floating-point tolerance, for the same ruleset and assumptions.

Output:

- Fighter A probability
- Fighter B probability
- Individual matrix edges
- Weighted contributions
- Three largest tactical influences
- Accessible weaknesses
- Inaccessible weaknesses
- Relevant NULL seams
- Compatibility effects
- Slot effects
- Expected range-control contest
- Tactical win paths
- Confidence and uncertainty classification
- Provenance and model version

Use deterministic computation.

Randomized outcome selection must use an explicit reproducible seed.

Never tune results solely to force a particular acceptance fixture to pass.
