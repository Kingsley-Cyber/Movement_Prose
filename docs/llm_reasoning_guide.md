# LLM reasoning guide

When Python execution is unavailable, say that the calculation and event drafting are manual. Never claim that the prediction program ran unless it actually did.

## Retrieval and calculation sequence

1. Resolve the two `fighter_id` values from `cards/`. Read their full dimension selections, adaptation, orientation, slots, active techniques and locked conditional abilities. A NULL is an uncovered capability; `kicking.none` is an explicit punch-only option.
2. Use `data/engine_index.json`’s `dimensions` index to retrieve only those option IDs. Read their adaptations, exposure weights, liability IDs and technique references. Pop-culture anchors explain the silhouette; they prove no mechanics.
3. In `data/matchups.json`, find each matrix by ID and then the exact `(row_id, column_id)` cell. Read both directions for asymmetric matrices. For the base cells, positive favors the row. Keep the mechanism and required lanes alongside the number.
4. Apply the adaptation and active-attack filter in `docs/model.md`. Then use the same-dimension edge once, or half of forward-minus-reverse for asymmetric matrices. Normalize only ruleset-available weights from `data/model.json`.
5. Retrieve each selected debt from `data/debt_registry.json`. Match its exploitation technique to the attacker’s active techniques and training. Standing access requires adjacent ranges. Ground access requires a trained entry. A possible path is not a successful attack.
6. Add the net synchronized-slot term once. Apply the NULL penalty once per missing dimension only if the ruleset, trained entry, range and prerequisites allow access. A future conditional gate cannot be treated as initially active.
7. Sum the weighted contributions and the supplied slot/NULL terms, then apply the logistic formula. If arithmetic cannot be established, report the intermediate terms and the unresolved calculation; do not guess a percentage.
8. Explain early initiative, the preferred-range contest, the first reachable debt, subsequent openings and reversal risks. Read specific `COUNTERS` edges and their preconditions. Distinguish supported relationships from speculative storytelling.
9. Draft events through the ten phases in `engine/fight_director.py`. Each event names actor, target, technique, causal predecessor, time, preconditions, contact and effects. Use `data/techniques.json` for motion, setup, range, body configuration, grip and recovery. Consult `data/combinations.json` for possible transitions; they are never automatic success.
10. Preserve claim IDs, source IDs, CANON labels, card version and the original prediction. A directed winner is explicitly dramatized. Do not label a manual event graph as program-validated or physically verified.

## Targeted lookup

To inspect Maleek’s switch, retrieve `stance.switch`, `hands.shield52`, `kicking.dutch`, and the two composite records on his card. For a loaded-leg exploit, follow the opponent’s `.leg` debt IDs to `low_kick`, then inspect the pivot-to-low-kick combination. For a NULL tie, use the actual trained `double_leg`, `collar_tie` or `body_lock` entry on the opponent’s card. For Maleek’s locked tie, read `maleek.cage_plum` and all three gates, not a general grappling option.

The counter graph is indexed by stable source/destination IDs and typed edges. The technique/debt registries carry their own IDs. A source claim supports only the exact text in `data/claims.json`; it does not turn tactical scores into verified research.

## Manual event sketch

A jab setup follows observation and a feint. Its execution precedes an anticipated defense; explicit contact precedes a contact-triggered reaction. Recover before an angle pivot. A completed pivot may precede a low kick only when that technique is trained and the opponent’s loaded-leg debt is reachable. Carry its contact mark and fatigue forward. Keep anatomical limb identity tied to current orientation. A camera shot must contain preparation, trajectory, target contact and reaction for every important attack.
